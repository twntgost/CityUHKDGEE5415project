# 团队组合效应 · 设计提案 v0.1

> 作者 2026-10-12 提出：核心玩法同质化太严重，希望加入**团队组合效应**，并让**面试档案袋**从“收藏册”变成“团队名册”。本文是提案，不是已定规则。
> 现状：`rulesVersion=3.0`、存档 schema 3，档案袋已按 `role` 分组（“招聘运营专员 · 4 人”）。

## 一、为什么现在会同质化

现在每一份简历的决策是**独立**的：看完两份 → 标一个疑点 → 推一个。推完之后这个人只是档案袋里的一个头像，

- **不影响后续概率**（除了信任和晋升/离职的信任增减）
- **不影响其他人**（没有任何组合关系）
- **不影响可选范围**（永远只有当天两份）

所以最优解会收敛成同一个动作：**尽量推概率高的那份**。玩家的注意力全在“单张简历”，不在“团队”。这就是同质化的根源。

## 二、设计目标

1. 让玩家开始关心**“我现在最强的人是谁”**以及**“团队结构缺什么”**；
2. 让档案袋从**战利品陈列**变成**可用工具**（HR 的编制表）；
3. 尽量**复用已有数据**，不新增内容编写量（504 份简历已经写完了）。

## 三、三个属性：直接复用现成数据

| 属性 | 来源 | 说明 |
| --- | --- | --- |
| **能力** | `candidate.successBps` | 已经在内容里，就是推送成功率基数 |
| **忠诚** | 由履历推导 | 入职时长（工作日）+ 是否被晋升 + 是否被冷落 |
| **岗位** | `candidate.role` | 档案袋已按它分组 |

不新增内容字段，全部由现有数据推导——这是本提案能低成本落地的前提。

## 四、组合规则（第一版建议）

以**同一岗位分组**为单位计算，每组建议 2–4 人：

| 名称 | 触发条件 | 效果 |
| --- | --- | --- |
| **互补** | 同组内同时存在“高能力”与“高忠诚” | 全组 **+5 个百分点** 推送成功率 |
| **内耗** | 同组**≥2 人**能力都超过阈值 | 涉事者各 **−8 个百分点**，且离职概率上浮 |
| **定海神针** | 同组有 1 名“低能力但高忠诚”（晋升过、在职满 N 天） | **全队**离职概率下降 |
| **一枝独秀** | 同组只有 1 人且能力高 | 无加成、无惩罚（避免“堆人头”变成唯一解） |

阈值建议：能力 > 45% 算高能力；忠诚由“在职 ≥60 工作日 或 晋升 ≥1 次”判定。

**关键**：内耗必须是**真的痛**。否则玩家只会无脑堆高能力的人，同质化原地复活。

## 五、档案袋拓展（HR 名册）

档案袋从“看头像”升级为**团队面板**：

1. **每个人显示能力/忠诚两条细条**（复用现有能量格组件）；
2. **每个岗位组显示当前组合状态徽章**：`互补 +5%` / `内耗 −8%` / `稳定`；
3. **组评级 A/B/C**：由组内平均能力 + 忠诚分布算出，直接影响**每月信任漂移**；
4. **同职位的新玩法（HR 本职）**：
   - **带队**：晋升过的人给同岗位新入职者加成（新人前 30 个工作日 +3 个百分点）；
   - **内部调岗**：每半年一次，把一个人调到另一个岗位，用来**拆内耗**或**补互补**；
   - **梯队提示**：某岗位出现内耗时，档案袋直接给一句“这两人在争同一个位置”。

## 六、对核心循环的影响

只有一处需要动概率公式：

```
推送成功概率 = 简历基础值 + 审阅正确奖励 + 运气 + 团队加成 − 内耗惩罚
```

（现有 `REVIEW_SUCCESS_BPS = 2500`、`MAX_SUCCESS_BPS = 9000` 不变，团队项也受 9000 上限约束。）

其余全部是 UI 与提示层，不碰存档结构以外的规则。

## 七、实施分期

| 阶段 | 内容 | 风险 |
| --- | --- | --- |
| **P1** | 三个属性推导 + 组合规则进概率公式 + 每日简报显示 | 低：只动一处公式 |
| **P2** | 档案袋团队面板（属性条、组合徽章、组评级） | 低：纯 UI |
| **P3** | 内部调岗 + 带队加成 | 中：新增命令与存档字段 |
| **P4** | 组评级影响信任漂移 | 中：会改变结局走向，需重新校准 |

建议**先做 P1+P2**：它已经能让“推谁”这件事从单张简历变成团队决策，而且存档结构几乎不用改。P3/P4 等作者验收 P1/P2 的手感后再上。

## 八、待作者拍板

1. **内耗惩罚力度**：−8 个百分点会不会太狠？
2. **阈值**：能力 >45% 算“高能力”是否合适？
3. **组规模**：按现有内容，同一岗位最多会积累到几人？如果经常只有 1–2 人，组合效应触发太少，需要放宽到“跨岗位”或降低人口门槛。
4. **要不要“换人”动作**：现在推送机会每天固定两份，玩家能否主动淘汰某人？（会显著改变节奏）
