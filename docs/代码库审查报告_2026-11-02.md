## 四、结构性问题（不是文件冗余，但值得记一笔）

1. **`MainActivity` 的窗口颜色设置在 API 35+ 上已失效**：`window.statusBarColor` / `navigationBarColor` 从 API 35 起弃用并被系统忽略（targetSdk 35+ 强制 edge-to-edge）。保留是为了 Android 7–14 仍能同色，已加 `@Suppress("DEPRECATION")` 与注释说明。
2. **edge-to-edge 的 inset 处理不统一**：`MainActivity` 调用了 `setDecorFitsSystemWindows(window, true)`（API 35+ 会被忽略），而工作台又自己加了 `statusBarsPadding()`。在 API <35 的机器上可能出现**双重内边距**。目前没有低版本设备可测，属于已知风险，建议后续统一改成显式 edge-to-edge。
3. **测试源码目录**：`app/src/test/kotlin` 与 `app/src/androidTest/kotlin` 是有效目录，旧的 `java/` 空目录已删。

## 五、检查方法（可复现）

- 未引用文件/符号：脚本扫描全部 `.kt` 的顶层声明名，在其它文件中反查引用
- 未引用资源：`R.font.*` / `R.string.*` / `@string/` 反查
- 未使用依赖：提取 `import` 前缀集合，与 `build.gradle.kts` 声明比对
- 死代码：`@Suppress("unused")` 标记 + `private fun` 全项目调用计数
- 编译告警：`./gradlew compileDebugKotlin --rerun-tasks` 捕获 `w:` 行
- 内容资源：在 `month1.json` 中反查 `assets` 相对路径的真实引用次数
